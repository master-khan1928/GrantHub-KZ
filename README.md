# GrantHub — ИИ-агент по грантам и стипендиям

Telegram-бот и сайт с одинаковыми функциями: каталог грантов, поиск, избранное,
профиль, ИИ-консультант, напоминания о дедлайнах и админ-панель со сканером.
Оба работают на одной базе данных и одной локальной модели Ollama.

## Структура проекта

```
├── core/                  общее ядро (используют и бот, и сайт)
│   ├── database.py        SQLite: гранты, пользователи, избранное, события, мониторинг
│   └── ai_scanner.py      LLM (Ollama / Gemini), ИИ-консультант, сканер университетов и конкурсов
├── telegram_bot/
│   └── bot.py             Telegram-бот (aiogram), планировщик сканирования и напоминаний
├── website/
│   ├── web.py             сайт (FastAPI) — REST API + отдача фронтенда
│   └── static/            index.html, app.css, app.js — одностраничное приложение
├── data/                  grants.db (создаётся автоматически)
├── logs/                  bot.log, web.log
├── backups/               старые копии файлов, не используются
├── run_bot.py             запуск бота
├── run_web.py             запуск сайта
├── .env                   настройки (токены, модель, расписание) — см. .env.example
└── requirements.txt
```

## Запуск

```powershell
.venv\Scripts\python.exe run_bot.py     # Telegram-бот
.venv\Scripts\python.exe run_web.py     # сайт: http://localhost:8000
```

Бот и сайт можно запускать одновременно. Перед запуском должна работать Ollama
с моделью из `OLLAMA_MODEL` (`ollama pull qwen3:4b`).

## Настройки (.env)

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN`, `ADMIN_ID` | токен бота и Telegram-id администратора |
| `LLM_PROVIDER`, `LLM_FALLBACK` | `ollama` (локально) или `gemini`; запасной можно оставить пустым |
| `OLLAMA_URL`, `OLLAMA_MODEL` | адрес сервера Ollama и модель |
| `SCAN_HOURS` | часы плановых запусков сканера, через запятую |
| `WEB_ADMIN_TOKEN`, `WEB_PORT` | токен админ-панели сайта и порт |
| `WEB_RUN_SCHEDULER` | `1` — сайт сам запускает плановый сканер (если бот не запущен) |

| `SWEEP_MAX_MISSES` | сколько запусков подряд грант может не встретиться в поиске до снятия автоочисткой (по умолчанию 6) |
| `REVIEW_MODE` | `doubtful` — на проверку идут записи с неподтверждённой страной; `all` — все новые |
| `API_RATE_LIMIT`, `CORS_ORIGINS`, `STATIC_MAX_AGE`, `SENTRY_DSN` | лимит запросов к API с IP в минуту, разрешённые сторонние домены, кэш статики, отслеживание ошибок |

## Казахстан и зарубеж: как разделены данные
Раздел каталога определяется полями базы, а не текстом описания.

| Поле `grants` | Смысл |
|---|---|
| `country_code` | страна, где проходит учёба (ISO-2); пусто — несколько стран |
| `provider_country` | страна, которая выдаёт грант («Болашак»: выдаёт `KZ`, учёба за рубежом) |
| `is_domestic` | вычисляется базой: `1` только при `country_code = 'KZ'`, вручную не задаётся |
| `record_status` | `active`, `archived`, `draft`, `flagged_review` (поле `status` — это статус приёма заявок) |
| `archived_reason` | `sweep` (автоочистка), `manual`, `duplicate` |
| `deadline_date`, `application_start_date` | дедлайн подачи и дата открытия приёма (YYYY-MM-DD) |
| `is_ongoing`, `recurrence_period` | приём круглый год (очистка не трогает); `yearly` — ежегодный грант |
| `source_id`, `external_id` | парсер (`seed` / `ai_scanner`) и нормализованная ссылка — уникальный ключ для upsert |
| `data_hash`, `last_seen`, `missed_scans` | хэш содержимого, когда запись в последний раз встретилась, сколько запусков подряд пропущена |

- Вкладка «Казахстан» — `is_domestic = 1 AND record_status = 'active'`, «Зарубеж» — `is_domestic = 0 AND ...`.
- Страну назначает `core/geo.py`: источник сканера (университет, программа) важнее слов модели. Если данные
  расходятся, запись получает `flagged_review` и ждёт решения в админ-панели («Очередь на проверку»).
- Поиск: название страны в запросе («Германия», «Казахстан») превращается в фильтр по `country_code`;
  раздел передаётся параметром `scope`, по тексту описания страна не ищется.
- Сканер обновляет существующую запись вместо дубликата. Запись, которая `SWEEP_MAX_MISSES` запусков подряд
  не встретилась в поиске, уходит в архив; если появится снова — вернётся сама. Снятое вручную не возвращается.
- Каждый запуск пишется в журнал (`scan_runs`): создано, обновлено, на проверку, в архив.

`GET /api/grants`: `category` (`kz` | `abroad` | `all`), `degree`, `country`, `funding` (`full` | `partial`),
`deadline` (`open` | `upcoming`), `req` (`ielts` | `toefl` | `sat` | `gpa` | `ent`), `limit`,
`cursor` — значение `next_cursor` из предыдущего ответа.

## Дедлайны и будущие гранты
- Ежедневно в 00:01 UTC (и при старте бота или сайта) гранты с прошедшим `deadline_date` удаляются насовсем;
  избранное, напоминания и подписки уходят вместе с ними.
- Бессрочные (`is_ongoing = 1`) не удаляются. У ежегодных (`recurrence_period = 'yearly'`) дедлайн и дата открытия
  переносятся на следующий год, статус становится «скоро откроется».
- Ссылка удалённого гранта запоминается на год (`grant_tombstones`): сканер не добавит ту же истёкшую страницу
  как новую, пока у неё не появится более поздний дедлайн.
- Статус приёма считается по датам: до `application_start_date` — `upcoming`, от неё до дедлайна — `open`.
- «Уведомить об открытии» (колокольчик на карточке будущего гранта, кнопка в боте): бот пишет в Telegram,
  на сайте появляется плашка вверху страницы. Писем сайт не отправляет.
- Флаги стран — эмодзи из `country_code`, без картинок. Для Windows, где эмодзи-флагов нет, подключается шрифт.

## Языки
Сайт и лендинг: переключатель Рус / Қаз / Eng в шапке, выбор запоминается в браузере, ИИ отвечает на выбранном языке.
Словарь — `website/static/i18n.js`. Бот: команда `/lang`, выбор хранится в базе (`users.lang`), словарь `T` в `telegram_bot/bot.py`.

## Безопасность (что сделано)
- Сессии и cookie посетителя подписаны HMAC (`SESSION_SECRET`), cookie `httponly`, `secure` на HTTPS.
- Пароли — PBKDF2-SHA256, лимиты на вход и регистрацию по IP.
- Лимиты на вопросы к ИИ по IP (8 в минуту, 150 в сутки) — защита квоты Groq.
- Ответы ИИ проходят санитизацию HTML на клиенте (только безопасные теги, ссылки только http/https).
- Проверка ссылок сканером не ходит на внутренние адреса (защита от SSRF).
- Защитные заголовки: `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, HSTS.
- Админ-панель сайта — по токену `WEB_ADMIN_TOKEN`; команды бота для админа — только для `ADMIN_ID`.
- Лимит на все запросы к API: `API_RATE_LIMIT` в минуту с одного IP; 10 неверных токенов админа — блокировка на минуту.
- CORS: чужим доменам API закрыт, пока они не перечислены в `CORS_ORIGINS`.
- Параметры каталога и поиска проверяются по спискам допустимых значений; тексты от сканера сохраняются без HTML-тегов.
